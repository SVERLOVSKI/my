# Карта React: что нужно закрыть руками

Структура повторяет раздел **Learn** на [react.dev](https://react.dev/learn) (версия доки под React 19).
Каждый пункт — одна тема, которую нужно не прочитать, а написать пальцами в проекте [Reps](./project-reps.md).

Формат работы: читаешь страницу доки → сразу пишешь кусок фичи, где эта тема нужна → отмечаешь `[x]`.
Если тему невозможно применить на текущем этапе проекта — это нормально, она всплывёт позже.

## Часть 1. Describing the UI — описываем интерфейс

Рендер без интерактива: компоненты, разметка, данные сверху вниз.

- [x] **Your First Component** — компонент это функция, возвращающая JSX. PascalCase обязателен (иначе React считает имя HTML-тегом). Никогда не объявляй компонент внутри другого компонента.
- [x] **Importing and Exporting Components** — `export default` vs именованный экспорт, один компонент — один файл, структура папок.
- [x] **Writing Markup with JSX** — один корневой узел (или `<>...</>`), все теги закрыты, `className` вместо `class`, атрибуты в camelCase (`htmlFor`, `onClick`, `tabIndex`).
- [x] **JavaScript in JSX with Curly Braces** — `{}` для выражений, `{{ }}` для объектов (inline-стили), где фигурные скобки работают, а где нет.
- [x] **Passing Props to a Component** — пропсы как аргументы функции, деструктуризация в сигнатуре, значения по умолчанию, `children`, spread `{...props}`, **пропсы read-only**.
- [x] **Conditional Rendering** — ранний `return null`, тернарный оператор, `&&` и ловушка с числом `0`, вынос условия в переменную.
- [x] **Rendering Lists** — `map` / `filter`, **`key`**: стабильный, уникальный среди соседей, не индекс массива при перестановках; `<Fragment key={id}>` когда нужно вернуть несколько узлов.
- [x] **Keeping Components Pure** — рендер чистый: не мутируем пропсы, state и внешние переменные; почему `StrictMode` рендерит дважды; где вообще можно делать side-effects (обработчики событий, эффекты).
- [x] **Your UI as a Tree** — дерево рендера vs дерево модулей; зачем это знать при разговоре о производительности и о позиции компонента в дереве.

## Часть 2. Adding Interactivity — интерактив

Состояние и события. Здесь ломается большинство джунов.

- [ ] **Responding to Events** — передаём функцию, а не вызываем её (`onClick={handle}`, не `onClick={handle()}`); именование `handleX` внутри / проп `onX` снаружи; всплытие, `e.stopPropagation()`, `e.preventDefault()`, фаза capture.
- [ ] **State: A Component's Memory** — `useState`, почему обычная переменная не работает, state локален и изолирован для каждого экземпляра компонента.
- [ ] **Render and Commit** — три шага: триггер → рендер → коммит в DOM. Понимать, что React не «перерисовывает всю страницу».
- [ ] **State as a Snapshot** — значение state заморожено внутри одного рендера; классика с тремя `setCount(count + 1)` подряд.
- [ ] **Queueing a Series of State Updates** — батчинг, updater-функция `setCount(c => c + 1)`, когда она обязательна.
- [ ] **Updating Objects in State** — иммутабельность, spread, обновление вложенных объектов, почему мутация «иногда работает» и это хуже, чем если бы она не работала вовсе.
- [ ] **Updating Arrays in State** — добавить / удалить / заменить / отсортировать без мутации: `map`, `filter`, `slice`, `toSorted`, `toReversed`; запрещённые `push`, `splice`, `sort` по месту.

## Часть 3. Managing State — архитектура состояния

Переход от «работает» к «спроектировано».

- [ ] **Reacting to Input with State** — декларативное мышление: перечислить визуальные состояния → определить, что ими управляет, вместо ручного дёрганья DOM.
- [ ] **Choosing the State Structure** — группировать связанное; избегать противоречивых, избыточных и дублирующихся state; **не хранить в state то, что можно вычислить при рендере**; избегать глубокой вложенности (нормализация).
- [ ] **Sharing State Between Components** — подъём состояния (lifting state up), controlled vs uncontrolled компоненты, single source of truth.
- [ ] **Preserving and Resetting State** — state живёт в **позиции** компонента в дереве; сброс через `key`; почему тот же компонент на той же позиции сохраняет state.
- [ ] **Extracting State Logic into a Reducer** — `useReducer`, экшены описывают «что произошло», а не «что поменять»; когда reducer читаемее набора `useState`.
- [ ] **Passing Data Deeply with Context** — `createContext` / `useContext` / `<Context>` как провайдер (React 19); **сначала попробовать композицию и `children`**, контекст — не замена пропсам.
- [ ] **Scaling Up with Reducer and Context** — reducer + context = локальный стор без внешних библиотек; разделение контекста состояния и контекста действий.

## Часть 4. Escape Hatches — выход за пределы React

Работа с внешним миром: DOM, таймеры, сеть.

- [ ] **Referencing Values with Refs** — `useRef` как «ящик», изменение не вызывает рендер, не читать и не писать `ref.current` во время рендера.
- [ ] **Manipulating the DOM with Refs** — ref на DOM-узел, **ref как обычный проп в React 19** (без `forwardRef`), ref-колбэк с функцией очистки, `flushSync`, список ref через `Map`.
- [ ] **Synchronizing with Effects** — `useEffect` как синхронизация с внешней системой, массив зависимостей, функция очистки, почему в dev эффект вызывается дважды и как это правильно чинить.
- [ ] **You Might Not Need an Effect** ⚠️ — самая важная страница раздела. Вычисляемое считаем при рендере, дорогое кешируем `useMemo`, сброс state делаем через `key`, реакцию на действие пользователя пишем в обработчике, а не в эффекте.
- [ ] **Lifecycle of Reactive Effects** — у эффекта свой жизненный цикл (начать / прекратить синхронизацию), реактивные значения, почему линтер прав насчёт зависимостей.
- [ ] **Separating Events from Effects** — `useEffectEvent`: нереактивная логика внутри эффекта.
- [ ] **Removing Effect Dependencies** — честные способы убрать зависимость: перенести в обработчик, разбить эффект, читать через updater-функцию, вынести объект или функцию наружу.
- [ ] **Reusing Logic with Custom Hooks** — правила хуков (только на верхнем уровне, только в компонентах и хуках), именование `useXxx`, кастомный хук делится логикой, но **не state**.

## Часть 5. Reference — справочник хуков и API

Подтягиваются по мере надобности в проекте.

**Состояние**

- [ ] `useState` — базовое состояние
- [ ] `useReducer` — сложные переходы состояний
- [ ] `useContext` — чтение контекста
- [ ] `useRef` — значение без рендера / DOM-узел

**Эффекты**

- [ ] `useEffect` — синхронизация с внешним миром
- [ ] `useLayoutEffect` — измерение DOM до отрисовки (редко)
- [ ] `useEffectEvent` — нереактивный колбэк внутри эффекта

**Производительность**

- [ ] `useMemo` — кеш вычисления
- [ ] `useCallback` — кеш функции (в паре с `memo`)
- [ ] `memo` — пропуск ререндера компонента
- [ ] `useTransition` — неблокирующее обновление + `isPending`
- [ ] `useDeferredValue` — отложенное значение для тяжёлого списка

**Формы и async (React 19)**

- [ ] `useActionState` — состояние экшена формы (`<form action={...}>`)
- [ ] `useOptimistic` — оптимистичный UI
- [ ] `use()` — чтение промиса или контекста, в связке с `<Suspense>`

**Прочее**

- [ ] `useId` — стабильные id для `label` и `aria-*`
- [ ] `useSyncExternalStore` — подписка на внешний стор (`matchMedia`, `localStorage`)
- [ ] `useImperativeHandle` / `useDebugValue` — знать, что существуют

**Компоненты и API**

- [ ] `<Fragment>`, `<StrictMode>`, `<Suspense>`, `lazy`, `createPortal`
- [ ] Error Boundary — единственное, что всё ещё требует классового компонента
- [ ] Метаданные документа (`<title>`, `<meta>` прямо в компоненте, React 19)

## Часть 6. TypeScript в React

- [ ] Типизация пропсов через `type Props = { ... }`, а не `React.FC`
- [ ] `useState<Task[]>([])` — когда нужен явный дженерик, а когда хватает вывода типа
- [ ] `ReactNode` для `children`, `ComponentProps<'button'>` для обёрток над DOM-элементами
- [ ] Типы событий: `React.ChangeEvent<HTMLInputElement>`, `React.FormEvent<HTMLFormElement>`
- [ ] Дискриминированные юнионы для экшенов редьюсера и для состояний загрузки
- [ ] `useRef<HTMLInputElement>(null)` и корректная работа с `null`

## Правила, которые нарушают чаще всего

1. `key` = индекс массива там, где элементы двигаются или удаляются.
2. Мутация массива или объекта в state (`arr.push(...)`, `obj.field = x`).
3. `useEffect` для того, что вычисляется прямо при рендере.
4. `useEffect` для реакции на клик — это работа обработчика события.
5. Вызов `setState` в теле компонента без условия → бесконечный цикл.
6. Подавление предупреждения линтера про зависимости вместо устранения причины.
7. Контекст там, где хватило бы `children`.
8. Состояние, дублирующее пропсы (кроме осознанного «начального значения»).
