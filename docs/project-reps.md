# Reps — трекер практики

Мини-проект для этого репозитория. Цель — закрыть всю [карту React](./react-roadmap.md) руками,
не упираясь в бэкенд, дизайн и бизнес-логику.

## Что это

Приложение, в котором ты ведёшь собственную практику: алгоритмические задачи, темы React,
что решено, что завалено, что пора повторить. То есть ты пользуешься им, пока его пишешь —
это единственный надёжный способ не бросить пет-проект на третьем этапе.

Ключевая механика — **повторения**. Решённая задача не исчезает: через N дней она всплывает
в списке «пора повторить». Этот список нигде не хранится — он каждый раз вычисляется
из истории попыток. Отличный тренажёр темы «считай при рендере, а не держи в state».

**Без бэкенда.** Данные в `localStorage`. Сетевые задержки имитирует локальный модуль `fakeApi`
с `setTimeout` и случайными ошибками — этого достаточно, чтобы честно отработать загрузку,
оптимистичный UI и `Suspense`.

## Доменная модель

```ts
type Topic = 'algorithms' | 'react' | 'typescript' | 'css'
type Difficulty = 'easy' | 'medium' | 'hard'
type Status = 'backlog' | 'in-progress' | 'done'

type Attempt = {
  id: string
  date: string        // ISO
  minutes: number
  solved: boolean
  note: string
}

type Task = {
  id: string
  title: string
  topic: Topic
  difficulty: Difficulty
  status: Status
  sourceUrl?: string   // ссылка на LeetCode / доку
  attempts: Attempt[]
  createdAt: string
}
```

Всё остальное — счётчики, «пора повторить», статистика за неделю, streak — **вычисляется** из этого,
а не хранится рядом.

## Экраны

1. **Доска** — задачи тремя колонками по статусу, фильтры по теме и сложности, поиск.
2. **Задача** — детали, история попыток, форма новой попытки, таймер сессии.
3. **Сегодня** — что пора повторить + активная сессия с таймером.
4. **Статистика** — минуты по дням, разбивка по темам, процент решённых.

Роутинга не будет: переключение вкладок — обычный state. Роутер — отдельная тема и не часть доки React.

## Этапы

Каждый этап — один коммит (или несколько). Не переходи дальше, пока предыдущий не работает.
Колонка «Читать» — страницы из [карты](./react-roadmap.md), которые нужно открыть **перед** кодом.

### Этап 1. Статика и JSX

Читать: Your First Component, Importing and Exporting, Writing Markup with JSX, JavaScript in JSX.

Свёрстанный на Tailwind каркас: шапка, три колонки, карточка задачи. Данные — захардкоженный
массив в `src/data/seed.ts`. Никакого state.

Приёмка: страница рендерит 6 задач из массива, компоненты лежат по файлам, `npm run build` проходит.

### Этап 2. Пропсы и композиция

Читать: Passing Props, Conditional Rendering, Rendering Lists, Keeping Components Pure.

`TaskCard`, `Badge`, `Column`, `EmptyState`. Карточка рисует бейдж сложности цветом, у задачи
без попыток — плашка «не начата». Колонка без задач показывает `EmptyState` через `children`.

Приёмка: ни один компонент не знает про глобальный массив — всё приходит пропсами. Ключи не по индексу.

### Этап 3. События и первое состояние

Читать: Responding to Events, State: A Component's Memory, Render and Commit, State as a Snapshot.

Фильтр по теме и переключатель «только незавершённые». Форма добавления задачи
(controlled inputs, `useId` для связки `label` и `input`).

Приёмка: фильтры работают, форма добавляет задачу, ничего не мутируется.

### Этап 4. Иммутабельные обновления

Читать: Queueing a Series of State Updates, Updating Objects in State, Updating Arrays in State.

Смена статуса задачи, удаление, редактирование заголовка, добавление попытки в `attempts`.
Здесь же — сортировка списка через `toSorted`.

Приёмка: в коде нет `push`, `splice` и `sort` по месту; обновление вложенного `attempts` не мутирует `Task`.

### Этап 5. Подъём состояния

Читать: Reacting to Input with State, Choosing the State Structure, Sharing State Between Components, Preserving and Resetting State.

Поиск и фильтры переезжают в общего родителя. Модалка деталей задачи получает `key={task.id}`,
чтобы её внутренний state сбрасывался при переключении задачи.

Приёмка: нет ни одного state, который дублирует другой; счётчики в шапке считаются при рендере.

### Этап 6. Reducer

Читать: Extracting State Logic into a Reducer.

Всё состояние доски переезжает в `boardReducer` с типизированными экшенами
(`task/added`, `task/moved`, `attempt/logged`, ...). Дискриминированный юнион для `Action`.

Приёмка: редьюсер — чистая функция в отдельном файле, покрыт парой ручных проверок в консоли.

### Этап 7. Context

Читать: Passing Data Deeply with Context, Scaling Up with Reducer and Context.

`BoardProvider` раздаёт состояние и `dispatch`. Отдельно — `ThemeContext` (светлая/тёмная тема
через Tailwind `dark:`). Хук-обёртка `useBoard()` с понятной ошибкой, если провайдера нет.

Приёмка: prop drilling убран, но там, где хватало `children`, контекст не появился.

### Этап 8. Refs и DOM

Читать: Referencing Values with Refs, Manipulating the DOM with Refs.

Автофокус поля при открытии формы, скролл к только что добавленной задаче, хранение id
интервала таймера в ref. Ref передаётся как обычный проп (React 19, без `forwardRef`).

Приёмка: `ref.current` не читается во время рендера; таймер не течёт при размонтировании.

### Этап 9. Эффекты и кастомные хуки

Читать: Synchronizing with Effects, Lifecycle of Reactive Effects, Separating Events from Effects, Removing Effect Dependencies, Reusing Logic with Custom Hooks.

Таймер сессии (`useInterval`), сохранение в `localStorage` (`useLocalStorage`), дебаунс поиска
(`useDebounce`), горячие клавиши (`useHotkeys`), заголовок вкладки с активной сессией.

Приёмка: у каждого эффекта есть внятная функция очистки; ни одно предупреждение линтера
про зависимости не подавлено комментарием.

### Этап 10. Рефакторинг «You Might Not Need an Effect»

Читать: You Might Not Need an Effect (перечитать целиком).

Пройтись по всем `useEffect` и снести те, что не нужны: «пора повторить», статистика,
отфильтрованный список — всё это производные значения. Дорогие — в `useMemo`.

Приёмка: эффектов осталось столько, сколько реально синхронизируется с внешним миром
(localStorage, таймер, заголовок документа, клавиатура). Остальное считается при рендере.

### Этап 11. Async и React 19

Читать: `useTransition`, `useDeferredValue`, `useActionState`, `useOptimistic`, `use`, `<Suspense>`.

`fakeApi` с задержкой и случайными ошибками. Форма через `<form action={...}>` + `useActionState`.
Добавление попытки — оптимистично через `useOptimistic`. Вкладка «Статистика» грузится
через `lazy` + `Suspense`. Переключение вкладок — в `useTransition`.

Приёмка: UI не «моргает» и не блокируется, ошибка сети откатывает оптимистичное обновление.

### Этап 12. Полировка

Читать: Your UI as a Tree, `memo`, Error Boundary.

`memo` там, где профайлер показал проблему (и только там). Error Boundary вокруг доски.
Доступность: фокус-стили, `aria-label`, работа с клавиатуры. Адаптив на Tailwind.

Приёмка: приложение проходится клавиатурой целиком, React DevTools Profiler не показывает
лишних ререндеров при вводе в поиск.

## Правила игры

- **Пишешь руками.** ИИ — только для объяснений и ревью, не для генерации кода.
- **Один этап — один коммит** с осмысленным сообщением.
- **Не забегай вперёд.** Соблазн сразу сделать reducer и context на этапе 3 велик; смысл
  упражнения в том, чтобы прочувствовать, почему без них становится больно.
- **Не подключай библиотеки.** Ни стейт-менеджера, ни UI-кита, ни `date-fns`, ни `uuid`
  (`crypto.randomUUID()` уже есть в браузере). Единственное исключение — роутер, если после
  12-го этапа захочется.
- **Каждый этап заканчивается зелёным** `npm run build` и `npm run lint`.

## Альтернативы, если не зайдёт

Ту же карту тем закрывают: тренажёр флеш-карточек с интервальным повторением,
конструктор опросов с предпросмотром, или клиент к публичному API (фильмы, покемоны) с
избранным и пагинацией. Реже трогают reducer и refs — это придётся добирать отдельно.
